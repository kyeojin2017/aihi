# 병원 방문 & 하루 증상 기록 구현 플랜

## 1. 목표
건강일기 상단 서브메뉴 중 **"병원 방문"** 탭을 실제로 동작하게 만든다.
지금은 탭을 클릭해도 "오늘 기록" 화면이 그대로 보이는데, 이 작업 이후에는
"병원 방문" 탭을 누르면 **병원 방문 기록 목록 + 등록/수정 폼**이 보여야 한다.

동시에 md 기획서 항목 "0) 매일 증상 기록 칸"도 함께 구현한다.
"오늘 기록" 화면의 "오늘의 증상" 카드는 지금 정적 샘플일 뿐 실제로 저장되지 않는데,
이걸 **날짜별로 저장/조회되는 진짜 기록**으로 바꾼다. 병원 방문 여부와 상관없이
그날그날 증상을 남기는 게 md에서 명시한 요구사항이라, 병원 방문 기록과 같은
"하루 단위 기록"이라는 축을 공유하므로 이번 플랜에 같이 포함한다.

## 2. 범위

**포함**
- 하루 증상 기록칸 구현: 있음/없음 토글, 증상 태그, 통증 정도, 체온, 대처 메모를 날짜별로 저장/조회
- 병원 방문 기록 등록 / 수정 / 삭제 (CRUD)
- 병원 방문 목록 화면 (최신순)
- 캘린더와 연동: 증상·방문 있는 날짜에 점(dot) 표시, 날짜 클릭 시 그 날짜의 증상 기록 + 병원 방문 목록을 함께 필터링 (공유 `selectedDate` 상태)
- 가족구성원 선택과 연동 (사이드바에서 "본인/배우자/서준" 선택 시 그 사람 기록만 표시)
- 서브탭 전환 시 화면이 바뀌는 공통 구조 (다음 서브메뉴들도 이 구조를 재사용)

**제외 (다음 단계)**
- Supabase 연동 (지금은 `localStorage`에 저장 — 스키마 설계는 [02-supabase-schema.md](./02-supabase-schema.md) 참고, 실제 연동은 계정/프로젝트 준비된 다음 단계에서)
- 처방전 자동 중복확인 기능 (처방전 탭 작업 때 별도로)
- PDF/메일 내보내기

## 3. 데이터 모델

```js
// localStorage key: "healthDiary.visits"
{
  id: "uuid",
  memberId: "self" | "spouse" | "seojun" | ...,  // 사이드바 가족구성원과 매칭
  date: "2026-08-08",       // YYYY-MM-DD
  time: "09:40",            // HH:mm
  hospital: "서울연세내과의원",
  department: "내과",        // 내과/치과/안과/정형외과... (뱃지 색상에 사용)
  doctor: "박정우 원장",
  nextVisitDate: "2026-08-13" | null,
  diagnosisMemo: "급성 인두염 소견. ...",
  createdAt: "ISO datetime",
  updatedAt: "ISO datetime"
}
```

진료과(department)는 기존 캘린더 범례/진료과별 통계에 쓰인 색상 매핑을 그대로 재사용한다
(`js/main.js`의 `DOT_COLOR`, css의 `dept-bar-fill` 색상 참고).

### 3.1 하루 증상 기록 데이터 모델

```js
// localStorage key: "healthDiary.symptoms"
// 날짜 + 가족구성원 조합당 1건 (같은 날 다시 기록하면 덮어씀)
{
  id: "uuid",
  memberId: "self" | "spouse" | "seojun" | ...,
  date: "2026-08-08",        // YYYY-MM-DD
  hasSymptom: true,          // 있음/없음 토글
  tags: ["인후통", "오한"],   // 있음일 때만
  painLevel: 3,              // 1~5, 있음일 때만
  temperature: 37.8,         // 없어도 됨
  action: "타이레놀 1정 14:20 · 수분 1.2L",  // 대처/메모 (없음인 경우 통증부위+대처 메모로도 사용)
  createdAt: "ISO datetime",
  updatedAt: "ISO datetime"
}
```

## 4. 화면 구성

### 4.1 레이아웃 변경
현재 `.content-grid`는 `320px(캘린더) / 1fr(오늘 기록) / 296px(접종·사진)` 3단 고정이다.
"병원 방문" 탭에서는 우측 296px 컬럼(접종·검진/사진)이 문맥상 필요 없으므로,
탭별로 표시할 `<section data-view="...">` 블록을 미리 만들어두고 JS로 보이기/숨기기만 전환한다.

- `data-view="today"` — "오늘 기록" 대시보드 (레이아웃은 그대로, 증상 카드만 실데이터로 전환)
- `data-view="visit"` — 이번에 새로 만드는 병원 방문 목록 화면
- 캘린더 컬럼(좌측)은 모든 뷰에서 공통으로 유지 (뷰 전환과 무관하게 항상 보임)
- 캘린더에서 선택한 날짜(`selectedDate`, 기본값 = 오늘)를 두 뷰가 공유. 상단 "8월 8일 토요일" 타이틀도 selectedDate를 그대로 표시

### 4.2 하루 증상 기록 카드 (`data-view="today"` 내 "오늘의 증상")
- 기존 마크업(있음/없음 토글, 증상 태그, 통증 정도, 체온, 대처 입력)은 그대로 두고 정적 값 대신 `selectedDate` + 선택된 가족구성원 기준으로 `getSymptom()` 결과를 채워 넣음
- 값이 없으면 빈 폼 상태(있음/없음 미선택, 입력칸 placeholder)로 표시
- 태그/통증정도/체온/대처 입력을 바꾸면 자동 저장(또는 "저장" 버튼 클릭 시 저장 — 기존 "저장" 버튼 재사용)
- "없음" 선택 시 증상 태그·통증정도는 숨기고 통증부위/대처 메모 입력칸만 노출 (md 요구사항: 없음인 경우 통증 부위 등 입력 + 진통제 복용/대처 입력)

### 4.3 병원 방문 목록 화면 (`data-view="visit"`)
- 상단: "병원 방문" 타이틀 + 기록 건수 + `+ 병원방문` 버튼 (기존 버튼 스타일 재사용)
- 목록: 기존 "병원 방문" 카드 디자인(파란 좌측 라인, 진료과 뱃지, 날짜/병원/진료과/의사/다음예약/처치, 진단메모)을 그대로 재사용해 **여러 개를 최신순으로 나열**
- 캘린더에서 날짜를 클릭하면 그 날짜 기록만 필터링, 다시 클릭하면 필터 해제 ("전체 보기" 텍스트 버튼 노출)
- 기록이 없을 때: 빈 상태 메시지 + `+ 병원방문` 유도

### 4.4 병원 방문 등록/수정 폼
- `+ 병원방문` 클릭 → 목록 맨 위에 입력 폼 카드가 펼쳐짐 (별도 모달 없이 인라인)
- 필드: 날짜, 시간, 병원, 진료과(select), 의사 이름, 다음 예약일, 진단메모 — 기존 `.field`/`.field-box` 스타일을 `<input>`으로 교체
- 저장/취소 버튼
- 카드의 "수정" 링크 클릭 → 해당 카드가 같은 폼으로 전환 (등록 폼과 로직 공유)
- 카드에 삭제(휴지통 아이콘 또는 텍스트) 추가

## 5. 파일 변경 계획

| 파일 | 변경 내용 |
|---|---|
| `index.html` | `data-view` 섹션 구조 도입, "오늘 기록" 콘텐츠를 `data-view="today"`로 감싸기, `data-view="visit"` 빈 컨테이너 추가(내용은 JS가 렌더) |
| `js/main.js` | 기존 서브탭 클릭 핸들러를 "탭 active 토글"에서 "뷰 전환"으로 확장 |
| `js/storage.js` (신규) | localStorage 읽기/쓰기, CRUD 함수 (`getVisits`/`addVisit`/`updateVisit`/`deleteVisit`, `getSymptom`/`saveSymptom`) |
| `js/visits.js` (신규) | 병원 방문 목록/폼 렌더링, 이벤트 바인딩 |
| `js/symptoms.js` (신규) | "오늘의 증상" 카드를 selectedDate 기준으로 채우고 저장하는 로직 |
| `css/style.css` | 폼 입력용 스타일(`.field input`, `.field select`), 빈 상태 스타일 추가 |

캘린더의 `SAMPLE_MARKS` (하드코딩 샘플)는 이번 작업에서 실제 `getVisits()` + `getSymptom()` 데이터 기반으로 교체한다.

## 6. 작업 순서
1. `js/storage.js` — localStorage CRUD 함수 작성 (증상 + 방문 둘 다) + 샘플 시드 데이터 삽입(최초 실행 시)
2. `index.html` — `data-view` 구조로 리팩터링 (기존 "오늘 기록" 마크업은 손대지 않고 래핑만), `selectedDate` 개념 도입
3. `js/main.js` — 서브탭 클릭 시 `data-view` 전환 로직, 캘린더 날짜 클릭 시 `selectedDate` 갱신
4. `js/symptoms.js` — "오늘의 증상" 카드를 selectedDate 기준으로 읽기/렌더 (있음/없음, 태그, 통증정도, 체온, 대처)
5. 증상 카드 저장 로직 (있음/없음 전환 시 필드 노출 분기 포함)
6. `js/visits.js` — 병원 방문 목록 렌더 (읽기 전용부터)
7. 캘린더 dot 표시를 `getVisits()` + `getSymptom()` 기반으로 교체 (하드코딩 `SAMPLE_MARKS` 제거)
8. 병원 방문 등록 폼 UI + 저장 로직
9. 병원 방문 수정/삭제 로직
10. 날짜 클릭 필터, 가족구성원 필터를 증상 카드·방문 목록 양쪽에 연동
11. 브라우저에서 직접 등록 → 새로고침 → 데이터 유지 확인 (Playwright로 스모크 테스트)

## 7. 다음 단계 (이 작업 이후)
- 같은 `data-view` 패턴으로 처방전 / 접종·검진 / 사진 기록 / 통계·리포트 탭도 확장
- `js/storage.js`를 나중에 Supabase 클라이언트 호출로 교체 (함수 시그니처는 그대로 유지해서 교체 비용 최소화)
